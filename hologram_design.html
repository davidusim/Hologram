Hologram Design Document

A detailed approach to creating a Pepper's ghost hologram display using software and accessible hardware.

1. Type of Hologram

We propose implementing a Pepper's ghost hologram using a four-sided pyramid configuration. This technique creates the illusion of a floating 3D object by reflecting images off transparent surfaces at specific angles. The pyramid allows for 360-degree viewing, making the hologram visible from all sides.

Pepper's ghost was chosen because:

  • It requires only commonly available materials (transparent acrylic, monitor/smartphone)
  • The optical principle is well-understood and reliable
  • It can produce convincing 3D effects without specialized holographic film or lasers
  • The software implementation is feasible with standard 3D rendering libraries

2. Required Hardware/Components

The hologram system consists of the following components:

  • Display Device: A monitor, tablet, or smartphone screen capable of displaying bright, high-contrast images. Ideally, a device with high brightness and good viewing angles.
  • Transparent Pyramid: Four trapezoidal pieces of clear acrylic or glass (typically 3mm thickness) joined to form a frustum (pyramid with the top cut off). Each trapezoid has specific dimensions based on the desired hologram size and viewing distance.
  • Optional Enclosure: A dark box or hood to place over the pyramid and screen, reducing ambient light and enhancing contrast.
  • Mounting Structure: A simple stand to position the pyramid above the screen at the correct angle (typically 45 degrees).

Pyramid Dimensions (example for a 10cm tall hologram):

  • Top width: 1cm
  • Bottom width: 6cm
  • Height: 10cm
  • Each trapezoidal face is identical

3. Software Architecture and Algorithms

Overview

The software renders a 3D scene from four distinct viewpoints (corresponding to the four faces of the pyramid) and combines them into a single distorted image that, when reflected by the pyramid, appears as a coherent 3D hologram.

Architecture Components

  • 3D Scene Manager: Handles loading, updating, and managing 3D models, animations, and lighting.
  • Multi-Camera Rig: Four virtual cameras positioned at 0°, 90°, 180°, and 270° around the Y-axis, each looking at the scene center from a distance equal to the pyramid's dimensions.
  • Render-to-Texture Pass: Each camera renders the scene to an off-screen texture (render target).
  • Distortion Shader: Applies a trapezoidal distortion to each camera's output to match the pyramid face geometry.
  • Compositor: Combines the four distorted textures into a single image arranged for the pyramid layout.
  • Display Output: Sends the final image to the monitor/screen.

Algorithm Flow

  1. Initialize 3D scene with objects, lights, and materials.
  2. For each frame:
    1. Update scene animations/objects if needed.
    2. For each of the four cameras:
      1. Set camera position and orientation.
      2. Render scene to off-screen texture.
      3. Apply trapezoidal distortion via shader.
    3. Combine the four distorted textures into a single viewport (typically arranged as four quadrants, each distorted to a trapezoid).
    4. Output the combined image to the display.

4. Programming Language and Libraries

We recommend using JavaScript with the Three.js library for the following reasons:

  • Three.js provides a robust, easy-to-use 3D rendering engine with WebGL fallback.
  • JavaScript allows the hologram program to run in any modern web browser, making it accessible and easy to share.
  • The browser environment simplifies handling of display resolutions and full-screen modes.
  • Three.js supports render-to-texture, custom shaders, and post-processing effects needed for the distortion.

Key Libraries:

  • Three.js (r152 or later) - Core 3D rendering
  • Three.js PostProcessing - For effect compositing (optional)
  • GSAP (GreenSock) - For smooth animations (optional)

Alternative Options:

  • C++ with OpenGL/SFML for maximum performance (more complex deployment)
  • Python with Pygame and PyOpenGL (good for prototyping but browser deployment harder)
  • Unity3D (powerful but requires export to WebGL for accessibility)

5. Key Mathematical Formulas and Processes

Camera Setup

For a pyramid with height h and bottom width w, the cameras are positioned at:

// Camera distance from center (adjust based on pyramid dimensions) const radius = w / 2 + h; // Empirical starting point // Four cameras at 0°, 90°, 180°, 270° around Y-axis for (let i = 0; i < 4; i++) { const angle = (i * Math.PI / 2); // 0, π/2, π, 3π/2 camera.position.set( radius * Math.sin(angle), h / 2, // Height at pyramid midline radius * Math.cos(angle) ); camera.lookAt(0, h / 2, 0); // Look at center of pyramid }

Trapezoidal Distortion Mapping

Each camera's rectangular output must be mapped to a trapezoidal shape matching the pyramid face. For a face with:

  • Top width: a
  • Bottom width: b
  • Height: h

The vertical position y' in the trapezoid for a given source y-coordinate (0 to 1) is:

// y' ranges from 0 (top) to h (bottom) // Source y ranges from 0 (top) to 1 (bottom) of camera texture const widthAtY = a + (b - a) * (y' / h); // Horizontal position x' for a given source x (0 to 1) centers within widthAtY const x' = (x - 0.5) * widthAtY + 0.5 * b; // Adjust for bottom alignment

In practice, this distortion is implemented as a fragment shader that computes the source UV coordinates for each destination pixel.

Shader Pseudocode (GLSL)

uniform sampler2D cameraTexture; // Rendered view from one camera varying vec2 vUv; // Standard quad UV (0 to 1) // Trapezoid parameters (adjust per pyramid face) const float topWidth = 0.2; // Normalized top width const float bottomWidth = 0.8; // Normalized bottom width const float height = 1.0; // Normalized height void main() { // vUv.y goes from 0 (top) to 1 (bottom) float y = vUv.y * height; float widthAtY = topWidth + (bottomWidth - topWidth) * (y / height); // Center the width float xOffset = (vUv.x - 0.5) * widthAtY; // Map to texture coordinates (assuming texture covers full width) vec2 sourceUV = vec2( 0.5 + xOffset / bottomWidth, // Scale to [0,1] range vUv.y ); gl_FragColor = texture2D(cameraTexture, sourceUV); }

Combining Four Views

The final display arranges the four distorted textures as follows:

// Assuming screen width = W, height = H // Each view occupies a quadrant, but distorted to trapezoid // Top-left: Camera 0 (0° view) // Top-right: Camera 1 (90° view) // Bottom-left: Camera 2 (180° view) // Bottom-right: Camera 3 (270° view) // In practice, this is done by rendering each distorted texture // to the correct quadrant of the final output, or by using // a single shader that samples all four textures with appropriate UV offsets.

Conclusion

This design provides a practical pathway to creating a convincing hologram display using accessible hardware and open-source software. The Pepper's ghost pyramid approach balances visual impact with implementation feasibility, allowing users to experience 3D holograms without specialized equipment.

Next steps would involve prototyping the software with a simple 3D model (e.g., a rotating cube) and refining the pyramid dimensions and camera parameters through experimentation.
